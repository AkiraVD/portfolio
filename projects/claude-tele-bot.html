claude-tele-bot

A coding agent driven from a Telegram chat. The interesting part isn't reaching it from a phone — it's where the security boundary goes.

RoleSole designer and engineer
Built withTypeScript, Node, Docker
Core concernSandboxing an agent that runs arbitrary commands

The problem

An agent that can run shell commands is useful for exactly the reason it’s dangerous to expose over a chat app. The agent itself is unmodified — same binary, same tools. Everything I built sits around it.

The security boundary

The allowlist is enforced on the host

Validation happens in the bot server before input reaches the agent. The container never receives the allowlist, so nothing inside can read or reason about its own restrictions.

Credentials never cross the boundary

The .env is never mounted or copied in. The Docker child gets a deliberately minimal environment — PATH, HOME, and the one credential the agent needs.

Its own PID namespace closes the obvious hole

A process reading /proc/1/environ inside the container gets its own init, not the bot that spawned it — so the classic route to a parent’s environment isn’t there.

Structured events, not a scraped terminal

The CLI’s streaming JSON is the same event stream its own interface draws from, which is what makes live text, collapsible tool output and diffs possible in an app that only has messages.
