The problem

Wayland deliberately blocks the tricks X11 automation relied on: xdotool only sees XWayland clients, and GNOME 46 refuses the old screenshot D-Bus method outright. The usual fallback is pixel coordinates, which break the moment a theme or a window position changes.

Three mechanisms, chosen deliberately

Input goes in below the display server

Events are written to virtual devices via /dev/uinput, underneath the compositor, so every app receives them. No root: systemd grants the seat owner an ACL.

Controls are found by name, not by pixel

The accessibility bus exposes real names, roles and actions — so a script targets “the Send button”, and can invoke it without moving the cursor at all.

Capture through the portal, consent remembered

Screenshots go through xdg-desktop-portal over PipeWire: one consent dialog ever, and a restore token makes every later capture silent.

A preflight command instead of a support thread

uictl doctor checks every capability on a new machine and prints the exact command to fix what’s missing.
